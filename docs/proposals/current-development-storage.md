## 固定资源与执行入口

- 开发目录固定为 `/home/gem/CodexSymphony`，绑定到专用受限文件系统；原分支和未提交修改已归并。管理员创建的稀疏 ext4 镜像最大 96 GiB，实际挂载缺失时入口拒绝运行。它不代表整台机器或旧历史目录总占用已经受限。
- Gate 仅使用一个 `validation/gate/workspace`，同步新增、删除和文件模式，独立 Git 元数据可在隔离环境访问。共同文件锁覆盖验证槽位与清理。直接编辑仍须尊重冻结阶段；运行末尾核对来源，变化即拒绝 PASS。
- 本地普通与插桩编译各一个固定 target；每轮重新采集计数和来源清单。相同内容不重写文件，保留有效编译缓存。远端 PR 使用另外两个固定 target，并在切换任务前重置，以保持不可信任务间的隔离。
- 数据库最多两个固定测试槽位（主、HTTP），复用容器身份；每次启动清空整个临时集群，释放时停止。数据存储采用有界 tmpfs，日志限额为每个容器 2×1 MiB。异常中断保留 pending 并阻止下一轮覆盖；恢复需核对原始来源和产物。
- 远端入口只抓取 Git 对象，从精确提交核对整个已批准快照；开发 HEAD、索引与未提交内容不切换，不建立按任务增长的 clone。远端状态写入受限文件系统。
- 旧 GH-90 四个手工采集入口已撤下；旧开发控制器与远端服务先停用。新远端入口在受审安装后恢复，开发控制器在 #140 接入前保持禁止派发。

## 自动保留与回收

完成捕获须有来源归档、原始清单、宿主注册和通过的测量摘要，才能释放 pending。保留紧凑来源、测量、失败与耗时事实，不复制完整 checkout、node_modules 或 target 作为证据。`bounded_retention.py` 读取已安装保留程序的数量、时限和字节预算；入口收尾与独立 timer 都执行。完成运行的临时目录可回收，raw/binary 依照已批准策略回收；未知、正在运行和未完成捕获不猜测删除。

历史大目录不因新入口上线自动消失；旧账户、数据库、尚在使用的进程目录须独立核对。`CodexSymphony-migration-rollback` 仍有旧会话 cwd 引用，在退出或重启并核对后回收，不允许它承接新开发。
