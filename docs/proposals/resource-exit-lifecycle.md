# 资源退出机制：#140 配套提案

状态：**待实现、待验收**。2026-09-28 经 Codex 与 Claude 讨论收敛，用户授权记录到文档和 [Issue #140](https://github.com/musutrade/CodexSymphony/issues/140)。本提案不授权部署、删除历史资源或新增真实模型调用。

当前策略从 [存储与证据保留入口](../quality/evidence-retention.md) 读取；开发与发布遵循 [AGENTS.md](../../AGENTS.md)。本提案不替代已安装批准，也不提前取消未完成捕获的保护。

## 目标与范围

一个仓库一个固定开发工作区，串行执行。必要验证目录、编译缓存、测试容器使用有限固定槽位；不引入仓库内并行或按任务扩张的槽位池。物理槽位复用与每次尝试的独立身份、独立捕获记录同时成立。

资源创建、登记、准入、失败收尾、保全验证、到期回收、启动对账和有限重试均由程序执行。**Agent 被强杀且不再启动，退出机制仍能运行。** Agent 可以发起任务，不承担必须继续对话或执行命令才能完成的收尾步骤。

管理员负责权限、存储隔离和受审安装；用户处理独有代码的放弃或超额保留等决定。程序展示明确对象、原因和恢复操作，等待期间阻止相关范围继续扩张，不要求 Agent 判断是否可删。

产品运行时与开发宿主分别接入、分别验收。覆盖手工采集、完整 Gate、远端验证、恢复入口及产品准备/执行/交付；不能用某一个入口通过替代全部完成。#126 的完整失败诊断要求限定捕获及有效保留期间的完整性，不构成永久保留例外。

## 已有能力和具体缺口

以下是讨论时的源码事实，不是本提案已经实施的证明：

- [manual_capture.py](../../tools/quality-host/manual_capture.py) 已由宿主建立 `pending-capture.json`，存在未处理 pending 时拒绝下一轮；但 `layout.new_run()` 创建目录先于 pending 落盘，中间崩溃可能遗留未登记目录。
- [manual_measure.py](../../tools/quality-host/manual_measure.py) 已在测量后自动执行 `register(run)`，核对安装身份后调用完成捕获注册，并非所有新入口都依赖 Agent 手工 `--register`。但只有测量 PASS 才调用 `complete`；测量失败、阶段中断或无人继续调用下一阶段时，尚缺自动接管和失败收尾。
- [bounded_records.py](../../tools/quality-host/bounded_records.py) 已支持记录到期及可续删；定时回收已接入当前宿主。新工作是补齐失败与启动对账路径，而非另建一套清理平台。
- [产品存储生命周期](../storage-lifecycle.md) 仍保护未知准备归属、未对账 partial archive 和活动恢复材料；这些状态也必须纳入退出规则，不能只修开发 Gate。

## 1. 创建即有归属，两类登记分开

资源分配前持久化分配意图，绑定 repository、attempt、owner、generation、资源类别、受管根及额度。文件系统创建与账本不能跨系统假定原子：用可恢复的意图协议，启动时核对“已有意图未创建”和“已创建未完成登记”两种状态。

两类登记不得混淆：

| 登记 | 时点和含义 |
| --- | --- |
| 资源分配登记 | 创建前记录身份和容量责任；不表示采集完成、可回收或质量通过 |
| 完成捕获注册 | 完整 source-bound bundle 与独立 raw 清单存在并经核验后，由宿主自动登记；不得用空清单或资源登记冒充 |

每次尝试具有新身份和独立证据记录；开发/验证槽位和缓存复用。上次消费者和写入者未解除时不能覆盖；阻塞也不能通过另建目录绕过。

登记仓库数量和跨仓库总预算都有限。历史未登记材料进入待办并计入实际容量，明确处理期限；逾期阻断相关仓库，确认共享容量耗尽才全局停派。不自动删除归属不明的用户目录，不把未知材料转存另一处无限保护。

## 2. 失败收尾状态机与实际写入隔离

状态转换为：

1. 停止相关派发和新写入请求，持久化收尾意图。
2. 撤销旧 generation 的控制面写入资格，停止旧执行单元。
3. 核验整个受管执行单元已静止，持久化 quiescence receipt；核对恢复、交付及材料消费者，不能仅看 PID 消失或租约过期。
4. 按白名单保全独有工作与必要事实，**验证保全材料可恢复**。
5. 持久化删除/释放意图，在与消费者领取互斥的条件下幂等清理。
6. 核对清理结果后释放槽位，记录业务结果与收尾结果各自的状态。

阶段失败保留原身份及累计预算，重启从已持久化状态继续，不重跑已发生的交付副作用。测量 FAIL 可以完成安全收尾，但永不变成质量 PASS；必要材料缺失时阻断对应恢复/发布。恢复资料到期后明确不能原地恢复，重新验证产生新结果。

固定槽位独占锁、generation 与执行单元隔离共同生效。Broker/API/数据库在实际写入处核对 generation；**给记录加 token 不能隔离原生 POSIX 文件写入**。编译器、脚本及派生进程必须纳入受管 cgroup/容器，宿主确认全组停止后才能复用目录。持有文件描述符的残留子进程不得漏检。无法证明静止时阻塞，不另开槽位。

明确隔离前提：未受管交互会话或管理员写入不能被协议凭空约束。发现活动外部写入时不得释放；不支持的执行入口拒绝启动。失效租约、`flock` 释放或进程列表扫描均不能单独作为静止证明。

## 3. 保留类别、消费者和恢复校验

| 类别 | 退出规则 |
| --- | --- |
| 可重建缓存、临时输出、无消费者的原始测量及历史回执 | 按适用数量、期限、字节预算回收；原始附件到期不改写历史结果，也不能冒充仍可核验 |
| 当前交付/恢复/验证必需材料 | 消费者解除前保护；预算不足则停止相关派发，对账后转入适用回收规则 |
| 原账户累计用量、未知预留、未解决外部副作用等关键账本 | 不作为普通附件到期删除；有限预算内保存，超限停派并按明确的账本保留/导出流程处置，不重置累计事实 |
| 未提交、未跟踪、未推送的独有工作 | 单独登记并计入配额；不得自动放弃。达到上限停止相关仓库，等待持久交付或用户明确处置 |
| 业务数据库 | 计入容量，永不进入通用资源清理器的自动删除集合；业务自身授权的数据生命周期另行管理 |
| 未知归属与未对账 partial 材料 | 限期对账并限制继续写入；不猜测删除，不默认无限扩额 |

消费者以现有持久化任务、交付、恢复与对账关系为权威；必要时增加有来源的引用，不能建立互相漂移的第二套状态账本。引用须有精确材料身份、持有者、用途和解除条件。创建消费者/领取材料与删除必须互斥或事务串行化；不能仅凭 PR 未关闭就保护所有历史产物。

保全优先保存必要补丁、新增文件和独有 Git 对象，覆盖二进制、文件模式、未推送提交及必要的 index 状态。验证时不改动原工作；在有界临时恢复区重建并核对文件字节、模式及 Git 身份，完成后清理恢复区。仅“写了压缩包”或保存哈希不算恢复校验成功。校验失败保留原件并阻止释放。

日志、摘要、删除索引和待办本身也有有限预算。到期删除与“不可删、超限停派”必须由策略明确分类，不能把所有回执永久保护，也不能误删累计用量来腾空间。

## 4. 内外层容量和控制面保障

覆盖受管源码/验证目录、工具缓存、临时输出、日志、Docker 可写层/卷/镜像/构建缓存、数据库/WAL/备份、证据及清理记录。只管理本产品有明确归属的资源，不执行影响其他项目的全局 prune。镜像身份及允许版本由部署配置冻结，未引用旧版本按策略回收。

启动前预留、运行中测量和实际写入限制缺一不可；普通 `du/df` 轮询不能证明硬隔离。部署必须说明并验证受管路径、挂载身份、存储硬上限及不能绕过的执行边界。

稀疏卷内部上限仍成立，但不保证外层物理空间充足。必须同时检查内外层容量及在途预留；宣称硬容量保障须有管理员提供且核验的预分配、专用容量或等效隔离。共享外层仅做预检/监测只能描述为提前停止，不能验收为硬保障。具体部署方式另行审定，本提案不直接迁移 Docker data-root。

控制面保留空间必须能在数据区达到上限时提交收尾意图和错误记录；仅在同一个已写满的数据目录中配置“保留字节”不算满足。不承诺底层硬件或文件系统故障下零损失；相关故障边界在隔离环境验证。

trim 属于外层物理块回收，不能用卷内空闲冒充实际释放。当前专用 trim 仍待管理员认证安装；Agent 可准备和验证，获授权的安装渠道具备权限后才安装，不能绕过认证或修改已批准发行目录。

## 5. 独立收尾与故障作用域

正常结束触发、启动对账和独立 timer 共同覆盖，有限重试不调用模型。清理中断后依据原意图继续；路径、设备/inode、挂载和文件身份变化不自动认领为旧资源。

单项清理或扫描故障通常只阻断相关资源/仓库；确认共享容量耗尽等共同故障才全局停派。控制面显示对象、占用、保护原因、到期条件、失败步骤及恢复操作。业务完成不因清理失败改写为未交付，清理失败也不能显示已释放。

## 6. 可执行验收

采用假 Runtime，不调用真实模型、不占用 GH-90 原账户。真实文件/进程与故障注入在隔离存储及测试 Docker 环境执行，不影响业务数据库。保留到期使用可注入时钟，进程停止与租约安全仍使用适当的真实/单调时间边界，不靠快进掩盖活进程。

- [ ] 至少 30 轮成功、失败、重试、取消、强杀与重启；开发目录为 1，必要验证目录最多 1，容器数量不超过配置固定槽位数，不随 attempt 增长。
- [ ] 创建前、建目录后、登记前、保全中、删除意图后及删除中分别强杀/重启；无遗漏分配、无永久待处理垃圾，重复收尾幂等。
- [ ] 测量 FAIL、阶段无人继续和 Agent 强杀后不再启动，宿主仍接管并完成适用收尾；无法安全释放时给出准确的阻塞而非新开目录。
- [ ] 旧进程跨租约存活、子进程持有文件描述符、旧 generation 写入及两个入口竞争均被实际边界阻止；未经静止确认不复用。
- [ ] 消费者创建与材料删除竞争不误删；消费者解除、未知归属超期与未解决失败到期均按分类规则处理。
- [ ] 预置文本/二进制哨兵、文件模式、index 和未推送提交，保全后能恢复并逐项一致；业务数据库关键数据验收前后校验一致。
- [ ] 注入数据区写满、外层容量不足、Docker daemon 重启、删除中 `kill -9`、权限与挂载变化；控制面仍能在数据区满时落盘，故障不会写往替代路径。
- [ ] 冻结槽位数量、保留窗口、各类预算及判据；记录每轮及峰值的真实字节/目录/文件数。跨足够到期窗口后，可回收部分稳定在预算包络内，到期项确实消失；受保护部分到限明确停派，不声称全部账本大小与历史任务数无关。
- [ ] 产品与开发宿主分别提交入口覆盖和验收结果；未接入入口明确阻止或标为未完成，验收自身的临时材料也收尾。

## 迁移与完成条件

先实现并验证资源登记、失败接管、恢复校验及幂等收尾，再迁移受支持入口和历史待处理资源。随后同步 AGENTS.md 与手工采集文档：澄清“每次新捕获身份/记录”不等于“每次新工作区”，撤下被程序替代的手工兜底步骤。新路径未验证前不得提前删除保护规则。

本次文档与 Issue 更新只记录需求。实现仍须经过批准的精确来源测量、完整 Gate 和受审部署；达到上述运行时与长期容量验收后才能关闭 #140。存在脚本、timer 或双方讨论一致均不构成验收完成。
