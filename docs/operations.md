# Localhost 操作闭环（GH-22）

现有 Angular 22 / Material 22 应用提供需求工作台（表单与评审）、需求列表、需求详情与 Run 时间线、待办箱。继续使用仓库内 arc-admin token、共享页面样式及来源记录，不依赖本机参考目录。服务状态仍可从导航访问，不新增指标 Dashboard。

## 状态与接续

- Requirement 对象版本与输入修订、Run 状态、候选验证结果和 GitHub/CI 观察分别展示。GitHub 的陈旧观察显式标记 stale；执行成功不表示验证通过、PR 合并或业务 Done。
- 详情与待办箱每五秒只读刷新。读失败保留可见事实并禁用写操作；恢复连接后刷新当前版本。页面销毁仅停止浏览器轮询，不发送暂停、取消或 Runtime 生命周期命令。
- 评审/撤回使用已有业务版本接口。暂停、恢复、取消、重新检查通过 `POST /api/requirements/{id}/operations` 绑定对象版本和请求 ID。完全相同的控制重放返回已保存结果；冲突刷新后再操作。
- 回答通过 `POST /api/operator/questions/{id}/answer` 绑定问题版本。重复、失效或身份重复的回答被拒绝；暂停期间保存回答不会解除用户暂停。回答不修改 Contract 或执行授权。
- 取消前显示停止、保全、关闭关联 PR 和对账效果；持久化取消不等于收尾完成。收尾期间保持待办，后台确认完成后即使历史暂停/问题仍存在也不再展示该待办。
- 每项需求一张聚合阻塞卡，展示阶段、原因确认程度、已保存内容、已尝试动作、下一步与恢复位置。没有确认的原因显示未知；预检和验证原始失败信息经脱敏后展示，不生成推测诊断。

## 数据来源与限制

`model_call` 汇总同一需求全部 Run 的 input/cached/output 与模型调用数；任何调用的某项用量未知时，该项合计仍为未知。cached 是 input 子集。修复次数来自 `repair_reservation`，人工等待来自 Run 已持久化的累计等待计数，不能把未结算时间当作已观测事实。

迁移 0010 开始持久化阶段墙钟时间和介入原因，包括评审后的撤回；重新评审不会抹掉该介入。阶段时间包括等待，并非纯编码耗时；已经静止的 Run 不新开计时段。到 PR 时长来自需求创建和交接创建结果的持久化时间。零介入率标明 reviewed_to_submitted 阶段、分子和分母，只纳入指标采集启用后评审且已 Submitted 的样本，空样本不显示成功百分比。迁移前的缺失历史不补造。

当前材料索引来自所属 Run 的 `runtime_evidence`，可用和截断状态由实际记录产生。预览只读取该需求所属 Run 的数据库块，最多 16 块；没有用户输入的文件路径读取入口。预览和详情错误文本过滤凭证、认证头、私钥和带协议的连接地址。

#23 的压缩/过期、完整存储占用、预留、受保护字节、清理失败及容量阻塞生产者尚未交付；页面明确未接入，未增加虚构数据或提前实现清理服务。已有 `storage_guard` 环境存储故障独立展示。原材料缺失不改写历史验证结果，可通过输入、Run 与验证索引复盘。当前改动不构成 A10 或完整 A01 验收。

验证命令与实际结果见 [GH-22 验证记录](quality/gh22/README.md)。开发自测不替代指定发布提交的独立双 Gate。
