# 桌面与手机的执行事实、扩展恢复和通知

需求详情与待办继续读取同一持久状态。Requirement 的业务状态、各 Run、验证代次、
交付及独立验收分别显示；Run 退出、旧 PASS、通知 accepted 或 PR merged 都不能推导 Done。
本地 Git 交付显示目标引用、确认的交付版本和独立验收，不要求存在 PR。

## 核对当前工作

详情展示冻结输入修订、仓库版本、环境与扩展配置、Hook 身份，以及已记录插件调用的
冻结作用域版本和当前授权。没有准入记录不表示允许执行。环境观察保留期望、实际、
差异、错误及观察时间；未知数据与 `not_applicable` 分开。耗时只引用已有阶段记录。

项账户显示上限、已知用量下限、含未结算预留的累计敞口和未知调用数；cached input
属于 input，不另加一次。子项同时链接父组评审、冻结授权、依赖版本及父／子账本。
暂停、重启、重验或适配不清零账户。原始诊断仍使用同一受保护的诊断清单、完整性、
可用性、缺失原因及下载路径，详情中的日志预览不替代完整保留内容。

## 提交恢复决定

扩展故障卡展示原验证身份、候选、原生结构化故障、责任方、影响范围、恢复条件、
已保存决定和后继验证。页面不会根据退出码猜测根因。

1. 补齐能力后选择同候选重验，填写部署批准的计划摘要、恢复条件和理由。源码保持，
   后台生成关联验证代次，旧失败仍保留。
2. 需要修复交付能力时，额外核对部署批准的交付策略摘要。它仍须经过后台交付授权。
3. 已批准范围内的代码适配填写明确约束、允许的仓库相对路径和解除条件；后台将约束
   绑定关联 Run。超出原批准范围先完成变化评审。

保存使用当前对象版本、输入 revision、原验证 ID 和稳定请求 ID；重复输入重试沿用同一
请求 ID，修改输入会产生新 ID。失败或响应未知保留本地输入，不自动重放写操作。
暂停、取消、无法读取当前事实及正在提交时停用恢复操作；最终准入仍由后台核对。
`accepted` 只表示决定已持久接受，只有实际启动事实才表示会话启动。

## 模型、生命周期与通知

整组评审可逐子项显式覆盖项目默认 provider、model、effort 并填写理由。后台拒绝不支持
或未授权的组合，不静默替换；新的项目默认不会暗改冻结任务。详情分开展示冻结选择、
来源、能力版本、实际响应身份、匹配结果及每次调用用量；缺少实际身份或用量显示未知。

生命周期面板按持久序号分页读取，每页最多 100 条，显示事件的 revision、来源、时间及
各插件的 accepted／ignored／failed／unknown、尝试次数和已有渠道事实。插件接收不表示
渠道已发送或手机已收到。有限补投使用既有 API，保持事件身份、历史次数和仓库授权，
不会重跑业务。通知离线或失败时，持久待办仍可在页面读取。

既有暂停／恢复／取消及 M1 变化评审继续使用后台版本检查、停止保全和外部对账。
暂停重启不自动继续；取消和合并竞态保留真实合并事实，不显示为回滚。未完成收尾不释放
占用，取消不满足依赖。会话过期后重新登录也不会自动重放未完成写操作。

## 迁移与回退

无数据库迁移、协议版本升级或宿主策略变更。`operations.execution` 和验证代次字段是
现有读模型的增量；OpenAPI 和生成的 Angular 类型同步。旧消费端可继续忽略新增字段。
回退产品提交即可移除界面与投影，已持久的恢复决定、生命周期、预算、授权及诊断原件
仍保留在既有表中。回退不撤销已接受决定，不应删表、重置账户或恢复已取消工作。

[GH-89 记录](quality/gh89/README.md)。现场公网 Bark、实际手机收到通知及完整父子链现场
矩阵继续按 #90 和既有现场验收记录处理；受控测试不能替代这些事实。
