# 父 AC 覆盖映射与整组授权（M1-03）

在父子草稿中选择“评审覆盖、策略与整组预算”。逐项核对目标、AC、kind、顺序、依赖、仓库身份、策略版本、修复范围和预算，填写每项 AC 的受控机器检查，再保存评审版本并一次确认整组授权。手机和电脑使用同一数据库记录。

所有父 AC 都是必需项。勾选完整功能链的 AC 必须映射到最后一个 `validation_only` 集成项，该项必须直接或间接依赖全部代码项。其余 AC 可添加多个承担项，引用精确的子 AC 和验证步骤。每个代码项必须记录在前置已合并的 main 上独立验证和安全合并的评审理由。**存在映射不证明语义覆盖，更不证明业务完成**；覆盖语义由用户评审，未来执行证据另行记录。

父与子复用导入模型的不可变整组 revision：同一 Draft revision 内的父/子内容都精确绑定该版本。修改草稿产生新 revision；评审映射、机器验证、策略版本、修复范围或预算修改产生新的评审版本和历史记录。旧授权快照不改写。保存草稿或评审会将已有组队列标记为需要重新评审。当前无正在执行的组项；执行中编辑与调度属于后续 Issue。

确认在一个 PostgreSQL 事务中重新检查版本、必需覆盖、引用、依赖与顺序、每个 AC 的验证计划、仓库授权及预算；随后保存不可变授权快照、累计预算上限及唯一组队列。任一失败全部回滚。相同 request_id 和完整确认输入返回原授权收据；复用 request_id 修改输入、过期版本或对同一版本另发确认返回 409。收据是历史结果，最新状态以重新读取评审为准。

预算按 tokens、turns、模型工作秒数分别计量。每项不能超过仓库策略；父组总上限默认等于批准子项额度之和，可显式设更低上限。重新评审只更新上限，保留父组及稳定子项身份的累计已用量和在途预留；移除子项也不删除其历史账本。现阶段不启动执行、不预留调用、不扣款。后续调度必须同时检查项与组余额，不能将这里的授权收据当作绕过余额检查的执行令牌。

成功状态为“已授权 / 等待调度能力”，不是“验收完成”。父项不获取执行槽。组队列不连接旧单需求 Ready 或协调器领取路径；`draft-` 身份调用旧接口仍拒绝。旧独立单需求流程保持原行为。没有新增登录、自动合并、关联修复执行、validation_only 执行或最终父级业务验收。

仓库登记/撤销与组确认复用控制面的评审事务锁；自然语言生成仍只形成 Draft。机器验证沿用已支持的 `cargo_test` / `npm_test` 检查、选择器、期望结果和超时。修复范围只细化当前项的授权内容，不能增加仓库、网络、受控检查或修复次数。
