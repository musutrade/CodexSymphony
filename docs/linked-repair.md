# 原项关联修复（GH-88）

合并后和最终集成的代码失败继续占用原 Requirement。Run、GitHub 合并记录、
失败验证证据分别保存；修复不创建新的业务项，不重写已完成其他子项。

## 明确启用范围

仓库仍须具有已评审的 `bounded_v1` 和 M3 自动交付能力。新授权的
`review.items[].repair_scope`，以及 integration 中每个仓库的 `repair_scope`，
使用以下 JSON 字符串明确指定失败检查与可修改文件：

```json
{"schema":"linked-repair/v1","checks":{"merged-source-cargo-tests":["gh88-b05.json"]}}
```

文件是仓库根目录下的精确路径，不接受目录通配、绝对路径、父路径或 `.git`。
此映射授权该检查失败时在该仓库的这些文件中修复。多个仓库映射同一集成检查时，
按仓库 ID 串行处理，优先本轮尚未修复的仓库。已有自由文本继续兼容；
平台不会把自然语言推断成新增文件写权限，缺少明确映射会保留待办。
执行中新增仓库、文件或权限仍需评审变化部分，回答问题不能扩权。

启动前校验独立验证的来源身份、全部必需检查、输出摘要和原生代码错误，
再核对当前仓库策略、项/父组余额、共享修复次数。失败原件通过
`linked_failure` 关联原合并操作或原集成调用；`repair_reservation` 的
同一计数、资源预留和具体启动意图在同一协调器事务提交。

Broker 读取当前目标分支并确认它包含实际受影响版本，固定新基线。修复使用
新的 Run、分支及 PR，经过原有候选验证、CI 和合并流程。发布前对实际 Git
差异核对授权文件；无变化或范围外变化保留工作并阻塞。不强推或回滚主干。

修复合并后，代码子项重新执行适用合并后验收。`validation_only` 保持原 kind，
为每个仓库重建独立 checkout，只更新被修复仓库的精确版本并重跑全部集成检查。
新调用保留原失败 ID 与修复版本关联；旧 SHA 的成功证据不能成为新 SHA 的验收。
已阻塞的合并后调用如因旧分类器将明确的独立验收契约失败判为未知，协调器仅在
原 `binding.json`、`result.json` 和步骤日志仍可按受信身份及摘要重放时重新分类；
缺失或损坏的原件继续阻塞，不以新的执行结果替代原失败。
暂停、问题回答、Run 恢复、取消和冷启动沿用原任务控制及累计预算。

需求完成或取消清理完成后，其 PR 退出周期轮询，历史观察与时间仍保留。
在途、失败和取消尚未收尾的项继续对账，避免旧 PR 的网络请求使当前交付的能力
观察反复过期；不延长 60 秒有效期，也不将旧观察伪装为新鲜事实。

若存储保护在 Runtime 预留后、会话落盘前触发，协调器只在同一控制锁内确认
已知启动意图、无 Runtime 会话、无进程身份且无启动目录后，将该预留记为未派发的
Interrupted，并保存事件。存储复查后沿用原工作与额度恢复；有会话、启动目录或
未知来源时仍要求正常停止证明，不能由 PID 不存在推断安全。

集成监督进程在创建目录前预留对应的 hot 存储额度；后续扫描和启动复查使用同一
分配身份。每仓集成 checkout 只预留 workspace，不重复预留不存在的 Runtime、
数据库流和事件流。修复后的每次完整复验仍累计计费，不退回旧调用的分配，也不
放宽 Run、项或全局存储上限。

持久化探测遇到 PostgreSQL 已确认回滚的锁等待超时（`55P03`）时拒绝本次动作，
下一轮须重新完成写入和容量检查；不把正在进行的存储复查再次锁死。实际 I/O 失败、
数据库不可用、容量不足和结果未知仍保留持久停止锁，要求显式恢复。

## 迁移与回退

`0029_linked_repair.sql` 新增关联失败、不可变 Run 输入与当前执行输入视图，
并允许共享修复预留引用真实合并/集成失败，而非伪造 candidate_validation。
历史修复的 `source_validation_id` 保持原值；新旧预留必须且只能具有一种来源。
迁移不修改原 Requirement revision、子项 kind 或历史授权。

`0030_cancelled_group_queue.sql` 仅在取消收尾完成后移除对应执行槽位，
保留取消项与预算历史；依赖取消项的子项仍等待真实完成证据。全部旧子项明确取消并
完成清理后，后续独立组可以领取。构建脚本跟踪 migrations 目录，保证新增迁移
进入 SQLx 编译产物，不以旧二进制冒充新源码部署。

回退前暂停队列，停止并保全所有 Run，对账所有关联 PR 和未知合并请求。
存在 `source_validation_id IS NULL` 的新预留时，旧二进制不兼容这些在途任务，
应继续使用新二进制完成或明确取消收尾。保留数据库备份及全部失败/合并证据；
不能删除关联记录来满足旧约束，也不能将已合并 PR 宣称回滚。
在一次性迁移演练环境且没有新预留时，可先移除执行视图及函数、Run 输入表、
新来源约束/列和关联失败表，再恢复旧 NOT NULL 约束。生产不执行自动降级。
