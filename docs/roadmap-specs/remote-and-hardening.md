# 手机访问与执行加固候选

> Deferred · 仅可选扩展，非当前规范

## 已提升为日常 V1 的范围

手机操作、一个行动通知渠道、访问认证/源站隔离/会话与写请求保护、自动执行所需凭证与受信验证边界、日常备份恢复由[日常 V1 契约](../daily-use-v1.md)定义。
这些是首个日常版本前提，不再等待用户证明手机或自动合并“有实际需要”。S1/S4 可作为实现依据，不能替代验收；S3 的 Access 认证为历史方案，Tunnel 隔离方法需重新验证。用户名、密码认证以日常 V1 第 6.1 节为准。

## 仍可后置

arc-admin 视觉规范与共享样式复用已进入当前页面基线，见 [UI 复用规范](../ui-design-system.md)。暗色切换、设计系统扩展、完整视觉回归、SSE/PWA、多通知渠道、通用诊断与资源平台根据真实需要评估。
完整双租约、dispatch_epoch、worktree_leases 不因进入日常阶段就成为前置条件；单进程仍采用最小恢复闸门。
Harness-Gate 接入不重写 CRAP 等语义，按实际版本验证身份与固定入口，不降低现有质量要求。

## 网络授权候选

0a 使用可信开发环境和服务连通性检查；强制网络策略与不可信执行器属于后续独立能力。
未来若需要更窄授权，可评估独立执行环境/代理策略或经过实测的 session 能力；不假设上游已提供。
如果仍依赖全局 requirements 文件，需要评估所有受影响进程、变更授权、恢复及热更新语义，不能静默替换当前部署。

## 诊断与运维候选

只有固定探针仍无法解决的故障造成明显人工负担时，再考虑独立只读诊断 Agent。
候选报告区分 confirmed/suspected/unknown；模型假设不直接授权恢复、执行 shell 或修改预算。
通用 DiagnosticBundle/DiagnosisReport/DiagnosticAttempt/action catalog 不因进入 0c 自动启用。
