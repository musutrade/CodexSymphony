# 本地完整验证与 CI 证据核验

实施任务：[GH-143](https://github.com/musutrade/CodexSymphony/issues/143)。部署与验收状态以宿主批准、精确树完整 Gate 回执和对应 CI attempt 的保留记录为准；本文描述实现约束，不作为 PASS 证据。

## 问题与决策

本地发布前已由独立受信宿主执行完整 Gate，远端 CI 又执行一次相同的昂贵采集与测试。当前后端测试约 22 分钟，重复执行还触发宿主/adapter 超时。用户确认改为：**本地受信宿主完整验证，CI 仅核验证据；任何事件不得自动回退完整 Gate。**

本方案由 Codex 与 Claude 通过 Herdr 交叉评审。相关成本与并行试点见 #142；该试点第二轮存在未解释的测试失败，不能作为 Gate PASS。本 Issue 独立解决重复执行，不能把失败结果转换为成功。

## 实施范围

1. 为完整本地 Gate 建立不可变 validation_id 与宿主拥有的追加式事件索引，绑定源码、全部执行输入、环境、策略/批准、工具摘要、原始报告与保留证据。工作区提供的任意 PASS/JSON 不构成可信凭据。
2. 新增 v3 远端只核验入口。pull_request、main push、workflow_dispatch 及重跑均只核验。缺失、不匹配、过期、撤销或不完整立即失败，不启动测试、数据库、捕获或完整 Gate。
3. 独立 App 为当前仓库、SHA、run/attempt 生成新的核验回执，引用原 validation_id；保留原报告身份，不复制旧 nonce 或伪称重新执行。Actions 继续验证 App 身份与精确运行。
4. 核对当前 head/base 与合并候选；合并前证明源码和所有影响结果的输入等价。审计 Git SHA、历史、ref、时间等输入；无法证明等价时，合并前阻断或验证精确候选，不采用合并后再次全跑的兜底。
5. 区分完整 Gate 失败/撤销与 CI 传输/证据暂缺：同一输入后来完整失败不得被旧 PASS 掩盖；核验传输故障恢复后可再次核验原证据，不记成完整 Gate 失败。
6. 在现有容量预约内保留核验所需证据，明确到期、撤销、PR 关闭/合并后的释放条件与审计窗口；不无限保留、不扩充编译 target 或容器。证据失效需回本地恢复，不触发远端全跑。
7. 更新安装/部署、回退和开发流程。当前 v3 绕过旧 tree_reuse，不能仅开启旧开关。只比较执行宿主身份，不要求 Actions runner 等同 Rust 执行环境。

## 验收

- 成功路径：完整本地 Gate PASS 的最终精确输入，经发布远端读回匹配，产生可信 CI PASS；证明 CI 完整 Gate/测试/数据库启动次数为零。
- 各事件及重跑均不得调用完整 Gate；无证据、错误 SHA/tree、环境/策略漂移、报告篡改、撤销、失败遮蔽、head/base 变化、过期 attempt、保留过期均确定性拒绝。
- 核验临时失败可在修复后重新核验；不改变原失败记录、不重放签名或重写原报告。
- 合并前保护与输入等价规则经过审计；新检查不得在合并后才发现未验证组合。
- 遵守 AGENTS.md：候选代码先精确来源 coverage/CRAP，再普通检查，最终完整 Gate PASS 后发布；不放宽阈值和保护。
- 宿主部署以审计过的独立维护变更交付，保留旧 release/config 和回退路径；不能直接覆盖已批准代码或自造历史 PASS。

## 评审决议与上线边界

完整开发和验证顺序只由根目录 `AGENTS.md` 定义。以下是本任务附加验收条件，不是另一份执行清单。

- 本地完整 Gate、远端核验、实际产品验收是三个不同结论。核验回执明确记录未重新执行完整测试；原报告的 commit、nonce、run 和签名不得重写。
- 新完整 Gate 的 FAIL 和证据撤销属于同一输入身份的验证历史。CI 网络故障、核验超时或证据暂时不可达不写成完整 Gate FAIL；修复后通过新 attempt 再次核验，保留先前失败。
- 证据保留必须先有容量预约和明确到期时间。PR 关闭/合并后的释放须晚于依赖核验和规定审计窗口；不能在 main 核验前释放，也不能无限 pin raw。
- 不采用“合并 SHA 改变后再全跑”的默认方案。源码树相同只是输入等价的一部分；在完成 Git 元数据审计和等价规则审查前，不启用跨提交复用。无法证明等价的合并方式在合并前阻断或验证精确候选。
- 每个 PR（包括指向 PR head 的手动触发）在发布成功检查前，都必须具有绑定该候选的等价审计，即使 PR head 正是本地验证的 commit。精确匹配只说明当前提交的关系，不能免除合并前证明。主线上与本地验证 commit 精确匹配的提交可直接核验证据。
- v3 等价审计逐项记录读取者及其批准摘要，区分提交标签、源码文件选择、固定批准输入和未执行分支。文件选择绑定保留的源码清单和归档；固定输入绑定实际使用的 baseline 值；未执行分支引用具体执行链。结构、摘要和行文本校验不自动证明分类正确或分支不可达，仍需独立审计。
- 审计只覆盖其绑定的 approval、tree、validation_id、执行环境及环境证据，不是未来任意源码的通用许可。静态源码推断和运行 trace 必须标明各自范围；单次 trace 不代替二进制构建来源证明。保留归档的路径、字节和 Git 文件模式须与被核验 tree 一致。
- CI 不装项目依赖、不启动测试数据库、不执行仓库提供的脚本来证明自己可信。独立宿主从远端 Git 对象解析源码身份，以宿主拥有的证据和当前批准集合核验；Actions 只等待指定 App 的精确 SHA/attempt 检查。
- 证据核验必须检查当前 head/base 与运行有效性，在发布检查前再次核对。保护规则更新必须受控；本任务不降低现有 strict、管理员强制和指定 App 必需检查。
- 当前旧 `tree_reuse.py` 不是新入口：它受版本分支限制、只接受远端 PR 完整记录且使用旧报告路径。不能通过打开旧开关声称已实现本方案。

## 已知本地完整 Gate 前置修复

原失败 `run-95b4e26f5a33` 的报告明确为 backend adapter 在 120000 ms 超时。后端导出/来源校验/打包的既有独立测量约 83–150 秒；采用受审的每 collector 有界请求预算：backend 300000 ms，frontend 与 frontend-api 保持 120000 ms，请求有效期保持 900000 ms。预算继续包含在签名中，覆盖率、CRAP、版本和证据完整性要求均不改变。

这项修改属于宿主候选，必须先测量、独立审查、按独立维护流程安装并通过最终完整 Gate。旧失败不会因预算修改而升级为通过；新预算也不预先保证完整 Gate 成功。

测试数据库的既有 OOM 恢复授权原只保留于 GH-90 分支提交 `c7ed0ca`，未进入本任务基线。此次原样移入 `environment.lock.json`、`docker-compose.yml` 及两份环境测试，使测试槽资源恢复为该授权值；具体资源以锁为准，开发数据库不变。新宿主批准、固定测试槽与环境投影必须一致，旧环境回执不得替代恢复后的来源测量和完整 Gate。
